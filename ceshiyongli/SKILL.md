# 测试计划 & 测试用例 → 钉钉文档

给定需求描述或 PRD，生成测试计划 + 测试用例并创建到钉钉。

## 测试计划模板

```
**文档版本：** V1.0   **编制日期：** <当前日期>   **适用平台：** <Web/APP/小程序>   **测试类型：** <功能测试/专项测试/…>

## 1. 测试背景
<需求背景、版本概述>

## 2. 测试目标
<逐条列出测试目标>

## 3. 测试范围

### 3.1 本次测试范围
<具体测试内容>

### 3.2 不在本次范围
<明确排除项>

## 4. 总体测试策略
<测试方法、策略说明>

## 5. 测试前置条件
<环境、数据、账号等准备>

## 6. 核心测试场景

### 6.1 <场景分类>

| 编号 | 测试场景 | 预期结果 | 优先级 |
|------|----------|----------|--------|
| <XX-01> | <场景描述> | <预期> | P0 |

### 6.2 <场景分类>
...

## 7. 执行安排
<测试顺序、分工>

## 8. 缺陷判定
<阻断缺陷标准、非阻断缺陷处理>

## 9. 准入与退出标准

### 9.1 进入条件
### 9.2 退出条件

## 10. 测试证据与交付物
<截图、日志、测试结论等>
```

## 测试用例格式

```
**编制日期：** <当前日期>   **适用平台：** <Web/APP/小程序>   **用例数量：** N 条

## 1. 执行说明
<测试范围、环境、注意事项>

## 2. 测试用例清单

### <模块名>

| 编号 | 模块 | 用例标题 | 优先级 | 前置条件 | 测试步骤 | 预期结果 | 测试结果 |
|------|------|----------|--------|----------|----------|----------|----------|
| <编号> | <模块> | <标题> | <P0/P1/P2> | <条件> | 1. ...；2. ... | <期望> | |

### <模块名>
...

## N. 通过标准
- 共 N 条用例，核心 P0 用例执行通过
```

## 用例设计规范

- **P0**：核心流程、数据一致性、主链路
- **P1**：异常流程、边界校验、权限控制
- **P2**：UI 展示、体验优化
- 编号格式：`<项目缩写>-<模块缩写>-<序号>`，如 `HW-POST-001`
- 前置条件简洁，测试步骤按数字编号，预期结果明确可验证
- 同一模块用例放在同一表格

## 工作流程

1. 理解需求，梳理功能模块
2. 生成测试计划（单独一篇文档）
3. 生成测试用例（单独一篇文档）
4. 分别用 `keithyt06-quick-dingtalk-mcp_dingtalk_doc_create` 创建到钉钉

## 注意事项

- 测试计划和测试用例各为独立文档，分别创建
- 每篇文档的 markdown 内容上限 10000 字符，超长时截断或精简内容
